ORBCAFE × ORBIS — Visual adaptation reference

Color & typography pass over the existing ORBCAFE component library, bound to the ORBIS light corporate surface system with its matching dark mode. Interactions, hierarchy, copy and layout behavior are unchanged. Every specimen below renders in both modes.

1 — Brand tokens

One token system, two modes. Core values are the registered ORBIS palette; every derived tint/shade is an OKLCh mix of a core color (formula shown, computed hex in the handoff). Orange is a small-signal color only.

4 — Buttons & actions

10px radius, 1px borders, primary actions 44px minimum. Motion is quiet: 0.2s color transitions, no transforms on hover.

Hover/focus states are live — tab through and hover. Focus ring: 2px solid primary (dark: primary-300) + 1px offset.

5 — Inputs & selection controls

Standard fields 44px, dense table fields 36px. Focus = primary border + 3px primary-18% ring. Error family derived from orange, never pure red.

6 — Reports, tables & pivot

Surface header row, 1px row dividers, hover and selected row states, right-aligned tabular numerals, status chips. Pivot fields stay draggable chips — only colors change.

7 — Status & feedback

Discipline rule: positive confirmation and info use ORBIS blue, warning uses orange, error uses deepened orange. No green, no cyan, no purple — anywhere.
